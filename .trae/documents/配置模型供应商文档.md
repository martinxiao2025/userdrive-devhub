## 改动文件

只改 **`README.md`**：

1. 在 §2.3「用户级配置」之后插入新小节 **「2.4 配置模型供应商」**，原「2.4 日志」顺延为 **2.5**（同步 §1 目录无需改动，因为 README 无目录）。
2. 新小节包含五块内容：
   - **配置项**：表格列出 `Model:OpenAi:BaseUrl` / `Model:OpenAi:Model` / `Model:OpenAi:ApiKeyEnvironmentVariable` / `Model:OpenAi:RequestTimeoutSeconds`，每项写默认值、必填性（均为非必填，缺省即默认）；`API key` 值必须存在（默认环境变量 `DEVHUB_OPENAI_API_KEY`），否则 `openai:auth`。再补一行说明 `Execution` 参数（默认值即可，不必配）。
   - **位置与优先级**：`appsettings.json` 不含模型配置 → 只能写 `config.json`；`config.json` 路径（含 `--data-dir`/`DEVHUB_DATA_DIR` 变化）；`DEVHUB__...` 环境变量覆盖 JSON 且优先级最高；key 只用环境变量；**全部在启动时读取一次，改完必须重启**。
   - **PowerShell 示例**（一段可直接复制）：`[Environment]::SetEnvironmentVariable('DEVHUB_OPENAI_API_KEY','<YOUR_API_KEY>','User')` + 当前会话 `$env:DEVHUB_OPENAI_API_KEY='<YOUR_API_KEY>'`（`start` 继承当前进程环境）、写 `config.json`（UTF-8 无 BOM，`Model:OpenAi` + `Execution`）、`devhub-daemon.ps1 -Action stop/start`、`node scripts/smoke-mcp.mjs` 看 `providers = openai:ready, vscode:down`；另附 Copilot Chat 里调 `scheduler_status` 看 `providers[].state/detail` 的等价方式。
   - **BYOK 与 vscode.lm**：同时注册、按队列项 `preferred_provider` 精确选择、无静默兜底；定时任务固定 `openai`（并注明 `Execution:ScheduledProvider` 当前未被读取，切换只能靠 `dispatch_now(provider:"vscode")`）；`auto` 的优先级 openai → vscode → 回退 openai；vscode 的 ready 条件（扩展激活 + `vscode.lm` 有模型 + `/health` pid 一致）。
   - **状态对照表**：`ready` / `auth` / `down` / `no_model` 的含义与处理动作。
3. 保守修订 §4 已知限制第 4 条：把「真实模型调用未验证」表述改为「本机未配置 key 时未验证；配置步骤见 §2.4」，不删除未验证事实。
