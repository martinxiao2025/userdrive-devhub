# 交付与提问规则

## 交付结果的四段结构

1. **结论**：完成 / 部分完成 / 未完成。
2. **证据**：文件、命令、输出、对比。
3. **未覆盖**：没做的部分与原因。
4. **待决策**：需要人拍板的事项。

## 提问的判定

| 情形 | 处理 |
|---|---|
| 信息在工作区里能查到 | 自己查，不提问 |
| 信息可以从任务描述推断 | 按最保守的解释执行，并在结果里声明假设 |
| 信息缺失且猜错代价高 | 发起提问，任务挂起 |
| 信息缺失但可以先做不依赖它的部分 | 先做，剩余部分再提问 |

## 提问单的必备字段

| 字段 | 要求 |
|---|---|
| 问题 | 一句话，可回答 |
| 影响 | 这个答案会改变哪个决定 |
| 选项 | 有明确选项时列出，并标出推荐项 |
| 缺失输入 | 逐项列出，不合并成「相关信息」 |

## 挂起与恢复

- 挂起期间：不占并发槽、不计入重试次数、不产生结果。
- 恢复条件：有人回答，或任务被取消，或超过有效期。
- 超时后果：请求置为过期，任务置为失败并通知；不会自动用默认值继续。
- 任务内容变化：旧的提问与回答一并失效，需重新发起。
