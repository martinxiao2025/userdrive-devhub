# 结果回写与不确定项上报

本技能规定「做完之后怎么交代」，包括正常交付、失败说明与发起提问。

## 什么时候用

- 一个回合已经产出结果，需要写清做了什么、验证了什么。
- 任务缺少必要输入，继续执行只能靠猜。
- 用户问「任务到哪一步了」「为什么停了」。

## 交付结果时写什么

1. **结论先行**：一句话说明完成 / 部分完成 / 未完成。
2. **证据**：改了哪些文件、跑了什么命令、结果是什么。没有验证的不要写成已验证。
3. **未覆盖项**：明确列出没做的部分与原因。
4. **下一步**：需要人决策的事项，逐条列出。

结果进入 `awaiting_review` 后不代表任务已完成，必须经 `reviewer` 或人工审批。

## 什么时候发起提问

只有同时满足以下三条才提问：

1. 缺少的信息**无法从任务描述、工作区文件或已有结果**推断；
2. 猜错的代价高于停下来的代价；
3. 问题可以用一句话问清，并尽量给出选项。

提问内容必须包含：

- 一句话问题；
- 为什么现在必须知道（影响哪个决定）；
- 可选项（有就列，没有就说明需要自由文本）；
- 缺了哪些具体输入。

## 必须注意

- 一个回合最多提一个问题；已在等待回答时不要重复提问。
- 不要用「请确认」代替具体问题；不要问「还有什么要补充的吗」。
- 提问后任务会挂起：不占并发槽、不消耗重试次数，但也不会有结果，直到有人回答或超时。
- 超时的请求会被置为失败并通知，不会被当成已完成；确需继续时重新建任务。
- 回答只在本次任务内容不变时有效；任务内容变化后旧回答失效。
